# Alternating compiler speed and memory, 2026-10-23

This session alternates prompts 4 and 5 until 12:00 Europe/Paris. The campaigns use separate
external worktrees under `%LOCALAPPDATA%/swc-agent-builds/alternate45-20261023-0730`, with
checkout-local compilers and at most six compiler workers. Prompt 4 does not use timing or
profiling; every retained speed change has a structural proof.

| Prompt | Retained change | Compiler work removed | Validation |
| --- | --- | --- | --- |
| 4 | Skip a second full rank comparison for candidates with the same UFCS call shape | `compareCandidatesIgnoringReceiver` already compares all explicit-argument ranks and the default/generic tie-breakers. When both candidates bind a receiver, only their receiver rank remains for the full ranking; when neither binds it, the full ranking is already complete. This removes the repeated explicit-argument walk while preserving receiver-kind and receiver-constness tie-breakers. | DevMode build; semantic function filter: 55 ordinary and 28 expected-error inputs; generic filter: 60 ordinary and 28 expected-error inputs. |
| 4 | Reuse call-shape scratch capacities across overload candidates | `GenericCallShapeContext` is local to one candidate-collection call and is reused for each generic shape precheck and concrete/generic candidate. Clearing its vectors preserves their capacity between candidates, removing up to three `shrink_to_fit` calls and their deallocation/reallocation cycles when storage is expanded; normal scope destruction releases the storage at the end of the call. | DevMode build; semantic function filter: 55 ordinary and 28 expected-error inputs; generic filter: 60 ordinary and 28 expected-error inputs. |
| 4 | Skip relocation lookup for sanitizer functions with no calls | The existing function-property scan records whether any instruction has the call flag. Functions without calls cannot consult a relocation target during sanitizer dataflow, so they skip the full relocation-table scan and target-map insertions; functions with calls retain the same lookup and panic-edge behavior. | DevMode build; all 85 sanity tests pass. The existing optimizer-policy profile identifies the sanitizer pass as a recurring backend cost; no new profile or timing run was made. |
| 4 | Skip constant-fold propagation for empty SSA | Every constant-fold rewrite needs a virtual reaching definition or an SSA-derived known value. With a valid SSA snapshot containing no values, neither condition can hold, so the pass skips the known-value fixed point and its full instruction rewrite scan. | DevMode build; all 1,562 C++ tests pass, including constant-folding coverage. The existing optimizer-policy profile identifies constant folding among the most frequently called backend passes; no new profile or timing run was made. |
| 4 | Skip value numbering for empty SSA | Every numbering key and rewrite requires an SSA value for a virtual register; when `ssaState->values()` is empty, the pass cannot produce a match or rewrite and skips dominator setup and its full instruction scan. | DevMode build; all 3,937 native tests pass. |
| 5 | Apply outlier release to value-borrow SSA scratch | The value-borrow pass previously cleared its thread-local SSA state without the next function size, bypassing the existing large-to-small release policy. | DevMode build; all 3,937 native tests pass; three alternating six-worker `core_rebuild` pairs show 19.0 MiB lower peak working set (942.1 to 923.1 MiB) and 14.1 MiB lower commit peak, with a small unconfirmed timing cost. See [memory results](../../memory/20261023-alternate45/README.md). |
| 5 | Drop retained SSA buffers when a worker moves from an outlier function to a much smaller one | Reuse remains intact for similar function sizes; an oversized per-worker `MicroSsaState` is released before the next small function's optimization begins. | DevMode build; 1,627 C++ tests passed, including SSA; three alternating six-worker `core_rebuild` and `hello_build` rounds. [Memory results and profile limits](../../memory/20261023-alternate45/README.md). |
| 5 | Free CodeGen node payloads when their CodeGen job ends | `CodeGenNodePayload` objects now use a per-CodeGen arena, so the job releases its payload allocations when complete. The arena remains alive while a CodeGen job is paused; auxiliary payloads retain their existing allocation path. | DevMode build; 3,937 native tests passed; three alternating six-worker `core_rebuild` rounds. Paired median ratios: wall 0.837, CPU 0.771, commit peak 0.980, working set 0.986. See the incremental comparison in the [memory report](../../memory/20261023-alternate45/README.md). |
