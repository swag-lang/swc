How to read the measurements

  • MachineIntel Core Ultra 9 185H, Windows 11, AC power. Baseline x86-64, no -march=native or LTO.
  • AffinityExecution on performance cores ({{pin_mask}}, {{pin_cores}} cores); builds are not pinned.
  • SamplesSwag: {{budget_ms}} ms per task, {{min_reps}} to {{max_reps}} samples; fewer for controls. Rotating round-robin, minimum retained. Allocator results use medians.
  • Calibration{{calib_start}} ms then {{calib_end}} ms; spread {{machine_spread}}%. Rejected above {{drift_limit}}%; build controls rejected above {{build_control_limit}}%.
  • Bounds checksRust, Swift and C# retain their checks; Swag release and C++ do not. Build recipes differ; see bench/README.md.
  • ReferenceSpeed = best time / measured time within the same execution group. Native / AOT, JIT and interpreted scores are independent. Aggregate speed is the geometric mean of those ratios; the winner can change by task. Small gaps do not imply statistical significance.
  • Progress score100 / geometric mean of corrected task time / corrected reference task time. Version {{progress_version}} freezes {{progress_tasks}} workloads. The baseline is the first clean, complete campaign; incomplete campaigns have no score. New tasks do not silently enter this index.
  • Headline buildGeometric mean of fastest non-Swag build time / Swag release build time. 2× means twice as fast; below 1× means slower. Bytecode recipes participate.
  • Protocol{{protocol}}. Raw campaigns, toolchains and measurement rules: bench/README.md.
