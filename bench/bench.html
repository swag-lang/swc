How to read the measurements

  • MachineIntel Core Ultra 9 185H, Windows 11, AC power. Baseline x86-64, no -march=native or LTO.
  • AffinityExecution on performance cores (0x55401, 6 cores); builds are not pinned.
  • SamplesSwag: 2000 ms per task, 3 to 16 samples; fewer for controls. Rotating round-robin, minimum retained. Allocator results use medians.
  • Calibration47.2 ms then 44.8 ms; spread 24.0%. Rejected above 40%; build controls rejected above 25%.
  • Bounds checksRust, Swift and C# retain their checks; Swag release and C++ do not. Build recipes differ; see bench/README.md.
  • ReferenceHeadlines use measured durations and their sums against the non-Swag runtime with the smallest total over all tasks. Native / AOT and JIT / interpreted references are independent. Direct comparison cells use the competitor named in their row. Per-example rankings show measured times only. Small gaps do not imply statistical significance.
  • Progress score100 / geometric mean of corrected task time / corrected reference task time. Version 1 freezes 12 workloads. The baseline is the first clean, complete campaign; incomplete campaigns have no score. New tasks do not silently enter this index.
  • Headline timesSwag total − best non-Swag total across all displayed workloads. Competitors must have valid times for the complete panel. Native / AOT and JIT / interpreted references stay separate; compilation includes bytecode recipes. Negative differences mean less time; positive differences mean extra time. Totals sum each measured workload once; longer tasks weigh more. Each headline uses one rival for the whole panel. Tables and headlines use the same duration formatting. Ahead / close / behind counts use a ±1% display band. Memory remains the peak in MiB.
  • Trend arrowsCompare the previous accepted campaign with complete measurements on the displayed panel, under the same protocol. Each time value uses its own campaign's non-Swag runtime with the smallest total. Compare the displayed differences directly: green up = a lower difference; red down = a higher difference; neutral right = the same value at displayed precision. No machine correction or ratio changes that direction. The small value is the previous measured value. Memory arrows compare the two displayed peaks directly; a smaller peak is better. Hover an arrow for the reference campaign and matched panel. These are observed changes, not significance tests.
  • Other benchmarksSPEC CPU aggregates normalized ratios geometrically; the legacy history views retain that convention. The Benchmarks Game also shows distributions. The task counts complement the headline total by showing how broadly a gap applies.
  • Protocol2. Raw campaigns, toolchains and measurement rules: bench/README.md.
