struct Swag.Task #src

One piece of work the runtime runs on its own schedule, and the outcome it produces.

T is the type of the value the work produces; a task that produces nothing leaves it out. The body can fail: Swag.Task.take hands over either the value or the error, once.

A task owns the closure it runs. Everything that closure reaches by address -- an & capture, a borrowed buffer, the task value itself -- must stay alive until the task is observed finished, which is what Swag.Task.wait establishes. A task cannot be copied: the runtime borrows its storage while the work is in flight.

Destroying a task that still runs asks it to stop, then waits for it, including on an early return or a raised error: nobody can read its outcome any more, so the body may as well end. Captured storage must outlive that wait. Declare borrowed locals before the task; an owner with a task field must still wait before its own cleanup releases anything the task borrows. The body has its own error state: a joining caller's handled or pending error does not decide the body's defer #fail or defer #nofail. A handled child error leaves the caller's error intact.

A process with no worker thread runs the work inside Swag.Task.submit, so a submitted task always reaches its end; only the thread that runs it changes.

A task is worth submitting only when it carries real work. Publishing it, claiming it and observing it finish cost a few microseconds together, so a body below that runs faster where it was written. parallel for measures its own body and keeps short ranges on the caller; a task submitted by hand has no such protection.

struct Swag.TaskGroup #src

Owns a set of child tasks and joins every one of them before it is released.

The group is the lifetime that makes a spawn safe: a child can borrow anything that outlives the group, because the group cannot be released while a child is still running. Leaving the scope of a group joins its children, whether the scope ends normally, by an early return, or by a raised error. Children use the same isolated error state as Swag.Task, including when the joining caller executes them during cleanup.

A child can fail. The first error a child raises asks every other child to stop, and Swag.TaskGroup.join raises it once every child has finished. Leaving the group's scope joins the children too, but drops an error nobody joined.

Cancellation is a request, not a stop. Swag.TaskGroup.cancel raises a request every child reads through Swag.isCancelled; a child that never asks runs to its end. A group spawned from inside other work -- a task, a partition, another group's child -- also passes that work's request on to its children, so it must be joined before that work ends, which is what a group declared in the body does.

The group holds its first children itself and takes one page for each further batch, so a small group allocates nothing. Because that storage belongs to the group, a captured borrow must outlive the group: declare what a child borrows before the group that joins it.

attr Swag.BorrowSummary #src

Computed borrow summary of a function, consumed by the static borrow analysis.

Bit i of returns means the return value may borrow parameter #i; bit i of stores means parameter #i may be stored in storage that outlives the call; bit i*8+j of into means parameter #j may be stored into storage reachable from parameter #i after the call returns (packed 8x8); bit i of frees means the call invalidates what parameter #i points to (it reaches IAllocator.free or IAllocator.realloc); bit i of reallocates means the call may move or release the heap payload parameter #i OWNS, which is what invalidates the views taken into it; bit i of returnsPayload means the returned value is a view INTO that payload rather than merely a value that can reach parameter #i, which is what tells a container accessor apart from a factory handing back an object that keeps a back-reference. Emitted automatically in generated module APIs so summaries cross module boundaries; can also be written manually on a Foreign function. Bit i of returnsStorage means the result aliases parameter #i's storage, rather than carrying a reference to it in a separate allocation. It only applies to bits also set in returns. Its default preserves the direct-alias assumption of annotations that omit it; generated APIs emit the computed mask explicitly. observesExternal means the call may observe application borrowed storage through globals, thread-local state, hidden aliases, or callbacks. Its default is conservative. A manual false on a Foreign declaration promises that the native operation only observes application storage through its explicit arguments and invokes no callback that can observe other application storage. Parameter retention remains governed by the other masks. Ordinary function bodies always contribute their computed effects, even when this argument is explicitly false.

returnsIndirect and storesIndirect use the same parameter bits as returns and stores, but describe borrows carried by the value reached after one dereference of the parameter, rather than the address of that value. For example, copying source[] into destination[] can retain a pointer field inside the source value without retaining the source's address. These masks add facts; their zero defaults do not erase any direct-mask bits. Bit i of freesIndirect means the call invalidates the pointer held in parameter #i's pointee, without releasing the box holding that pointer. func Task.submit #src

Submits body for one execution.

notify, when given, runs once on the thread that finished the work, after the outcome is stored and before the task reads as done. It is how an owner on another thread learns that Swag.Task.take will not wait, for example by posting an event to a window. It must be short, and must not wait for this task.

A Background task runs its body at a lower thread priority. On the shared pool, background work is admitted in submission order against one process-wide CPU and memory budget. Pressure reduces new admissions; already running bodies finish normally. Normal work has priority, with bounded preference so admitted background work can still progress.

Waiting for a task promotes its queued work past admission; a direct wait can run it itself. This also applies to Swag.whenAll and Swag.whenAny. The budget is not a synchronization primitive or a memory guarantee: pool tasks must not block waiting for unrelated queued tasks. Use an Swag.Executor for thread-affine or blocking work. An executor runs the task on its own thread, in submission order, outside pool admission.

The task must not already be in flight. A task may be submitted again after it finished; an outcome nobody took is released then.
