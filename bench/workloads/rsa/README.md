# RSA SHA-256 reference fixture

The four fixtures use disposable RSA keys generated by Python cryptography 50.0.0 with public exponent 65537. The generator immediately verifies each signature and decrypts each ciphertext using Python cryptography. It also checks the CRT parameters against the modulus and private exponent.

The shared 48-byte message uses `(37*i + 11) & 255` for byte indexes 0 through 47. PSS uses SHA-256, MGF1-SHA-256 and a 32-byte salt. OAEP uses SHA-256, MGF1-SHA-256 and an empty label. The 2080-bit key exercises a modulus with 65 32-bit limbs.

`fixtures/manifest.json` identifies each concrete RNG-generated fixture by SHA-256 and retains the message bytes and SHA-256 of each randomized signature and ciphertext. Keep each fixture unchanged across benchmark samples. Running `generate.py` creates a new fixture set.

## Binary layout

The first 12 bytes contain three unsigned little-endian 32-bit lengths in order `W, M, E`, where `W` is the RSA modulus width in bytes, `M` is the message width and `E` is the public exponent width. The remaining data is contiguous with no padding.

| Field | Width in bytes |
| --- | ---: |
| Modulus `n` | W |
| Private exponent `d` | W |
| Public exponent `e` | E |
| PSS signature | W |
| OAEP ciphertext | W |
| Message | M |
| Prime `p` | W/2 |
| Prime `q` | W/2 |
| CRT exponent `dP` | W/2 |
| CRT exponent `dQ` | W/2 |
| CRT coefficient `qInv` | W/2 |

All numerical key fields, signatures and ciphertexts use unsigned big-endian byte encoding. `qInv` is the inverse of `q` modulo `p`. These fixtures use `M=48` and `E=3`.

## OpenSSL EVP

The C reference links against the Release build of OpenSSL 4.1.0 with its optimized default provider. Use the same 4.1.0 tree for headers and static library.

```sh
cc -O3 -Wall -Wextra -Werror -I"$openssl_dir/include" reference.c \
    "$openssl_dir/libcrypto.a" -pthread -ldl -o openssl-rsa
./openssl-rsa --version
./openssl-rsa rsa-pss-verify fixtures/rsa-2048.bin output.bin 100 1
./openssl-rsa rsa-oaep-decrypt fixtures/rsa-2048.bin output.bin 100 1
./openssl-rsa rsa-oaep-decrypt-d-only fixtures/rsa-2048.bin output.bin 100 1
python3 check.py
```

The reference imports `n,e` for PSS verification. It imports `n,e,d` and all five CRT parameters for `rsa-oaep-decrypt`, and only `n,e,d` for `rsa-oaep-decrypt-d-only`. It checks that OpenSSL exposes a prime factor on the imported full CRT key and that the `n,e,d` key has no factor.

Setup, file I/O and a successful warm-up operation are outside the measured loop. PSS hashes the message with SHA-256 during each iteration and verifies the prepared signature against that digest, using the same initialized key context. OAEP uses its initialized decryption context each iteration, with a fresh output length. It checks the full plaintext before and after the timed loop. OpenSSL's private-operation countermeasures remain active. Comparisons against raw-key Swag calls also include any key setup those calls perform each time.

On success the executable prints wall nanoseconds, process CPU nanoseconds and the wall frequency, space-separated, on one line. The output file contains byte `01` for successful PSS verification or the complete OAEP plaintext. The offset shifts the entire in-memory fixture before parsing. `check.py` verifies all three modes at offsets 0, 1 and 7 for all four fixture widths.

## Swag and the paired comparison

Run the following from this workload directory. Build both source snapshots
with the same Linux compiler and Release configuration, with `SWAG_PATH`
pointing to the `bin` directory of each snapshot.

```sh
python3 generate.py
SWAG_PATH="$before_repo/bin" "$compiler" build -d src --module-file module.swg \
    -bc release --artifact-kind executable --artifact-name swag-rsa \
    --out-dir "$before_out" --work-dir "$before_work"
SWAG_PATH="$current_repo/bin" "$compiler" build -d src --module-file module.swg \
    -bc release --artifact-kind executable --artifact-name swag-rsa \
    --out-dir "$current_out" --work-dir "$current_work"
python3 run.py --swag "initial=$before_out/swag-rsa" \
    --swag "windows=$current_out/swag-rsa" --openssl ./openssl-rsa \
    --fixture fixtures/rsa-2048.bin --fixture fixtures/rsa-2080.bin \
    --fixture fixtures/rsa-3072.bin --fixture fixtures/rsa-4096.bin \
    --cpu 4 --rounds 13 --output comparison.json --markdown comparison.md
```

The paired run compares every result byte to the fixture's expected result.
It takes process CPU samples on one pinned logical CPU and retains elapsed
wall samples. The paired CLI uses offset zero for all engines. For a direct
unaligned Swag check, prepend the requested number of padding bytes to the
file. The reference driver adds the displacement when reading the file.

The Swag public interfaces take encoded key integers on each call. OpenSSL
uses an EVP key and operation context prepared before measurement. The
`d-only` private comparison uses the same mathematical key inputs as the
Swag operation and retains the OpenSSL provider's countermeasures.
