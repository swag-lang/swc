How to read the measurements

  • MachineIntel Core Ultra 9 185H, Windows 11, AC power. Baseline x86-64, no -march=native or LTO.
  • AffinityExecution on performance cores ({{pin_mask}}, {{pin_cores}} cores); builds are not pinned.
  • SamplesSwag execution: {{budget_ms}} ms per task, {{min_reps}} to {{max_reps}} samples; fewer for controls. Rotating round-robin, execution minimum retained. Locally checked compilations use a minimum confirmed by a second sample within 10%. Unconfirmed lower samples remain in the raw record. Allocator results use medians.
  • Calibration{{calib_start}} ms then {{calib_end}} ms; probe departure {{machine_spread}}%. Execution-probe departures above {{drift_limit}}% reject a campaign. Build controls moving apart by more than {{build_control_limit}}% also reject it.
  • Bounds checksRust, Swift and C# retain their checks; Swag release and C++ do not. Build recipes differ; see bench/README.md.
  • ReferenceHeadlines use measured durations and their sums against the non-Swag runtime with the smallest total over all tasks. Native / AOT and JIT / interpreted references are independent. Direct comparison cells use the competitor named in their row. Per-example rankings show measured times only. Small gaps do not imply statistical significance.
  • Progress score100 / geometric mean of corrected task time / corrected reference task time. Version {{progress_version}} freezes {{progress_tasks}} workloads. The baseline is the first clean, complete campaign; incomplete campaigns have no score. New tasks do not silently enter this index.
  • Headline timesSwag total − best non-Swag total across all displayed workloads. Competitors must have valid times for the complete panel. Native / AOT and JIT / interpreted references stay separate; compilation includes bytecode recipes. Negative differences mean less time; positive differences mean extra time. Totals sum each measured workload once; longer tasks weigh more. Each headline uses one rival for the whole panel. Tables and headlines use the same duration formatting. Ahead / close / behind counts use a ±1% display band. Memory remains the peak in MiB.
  • Trend arrowsCompare the previous accepted campaign with complete measurements on the displayed panel, under the same protocol. Each time value uses its own campaign's non-Swag runtime with the smallest total. Compare the displayed differences directly: green up = a lower difference; red down = a higher difference. Neutral right = equal printed values. The tooltip reports sensitivity to replacing each selected minimum with its next observed sample; overlapping ranges or missing repeat evidence do not change the observed arrow direction. This leave-one-out check is not a confidence interval and cannot detect every systematic bias. A competitive gap can widen even when Swag itself runs faster. The small value is the previous measured value. Memory arrows compare the two displayed peaks directly; a smaller peak is better. Hover an arrow for the reference campaign and matched panel. These are observed changes, not significance tests.
  • Other benchmarksSPEC CPU aggregates normalized ratios geometrically; the legacy history views retain that convention. The Benchmarks Game also shows distributions. The task counts complement the headline total by showing how broadly a gap applies.
