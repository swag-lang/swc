Module net

Net provides blocking TCP and UDP, DNS resolution, bounded HTTP requests and servers, and URL helpers.

Connect over TCP

#import("net") using Net #main { var connection = try TcpStream.connect({address: [127, 0, 0, 1], port: 8080}) let request = cast(const [..] u8, "hello") var offset = 0'u64 while offset < request.count { let sent = try connection.write(request[offset to]) if sent == 0 do fail NetworkError{"TCP stream stopped accepting bytes", code: 0} offset += sent } }

Streams own their connections and close them on drop. TCP and UDP support IPv4 and IPv6 on Linux and Windows. TCP streams support no-delay mode, keepalive probes, read and write timeouts, and half-closing their send side. UDP supports broadcast and IPv4/IPv6 multicast membership. TCP and UDP blocking reads have configurable timeouts. Operations can fail or transfer fewer bytes than requested. DNS resolution preserves the platform resolver's address order and resolves named services. DNS lookup is synchronous and cannot be cancelled. HTTP and HTTPS clients and the HTTP/1.1 server are available on Windows and Linux. An HTTP server handles one request per connection by default. It can allow a bounded number of requests when an idle read timeout is configured; closing the server stops its listener while accepted connections remain independent. A blocked accept is not guaranteed to wake on close, so coordinate shutdown with accept callers. Http.post streams a length-bounded request body from a caller-provided reader.

Request an HTTPS resource

#import("net") using Core, Net #main { let target = try Url.parseHttp("https://example.com/?q=swag") let response = try Http.get(target.host, target.port, target.path, target.secure) if response.status == 200 do Console.println(cast(string, response.body.toSlice())) }

HTTPS verifies certificates and host names against the platform trust roots. Linux loads libcurl.so.4 on the first HTTP request and needs thread-safe initialization and asynchronous DNS support; TCP-only programs do not load it. Standard proxy settings remain effective, including NO_PROXY. SSL_CERT_FILE and SSL_CERT_DIR override Linux CA roots for the server and HTTPS proxy. Responses expose the final status, body, and ordered headers (including duplicate names). Requests have bounded response bodies and return redirects without following them, so the caller can decide which destinations are acceptable by default. GET can optionally follow at most ten redirects; HTTPS requests cannot downgrade to HTTP, and redirect following rejects origin-sensitive request headers. POST never follows redirects. Net.Http.get documents timeout and header limits.

Exchange WebSocket frames

#import("net") using Core, Net #main { var peer = try WebSocket.connect("example.com", 80, "/events") try peer.sendFrame(.Text, cast(const [..] u8, "hello")) let frame = try peer.receiveFrame() if frame.opcode == .Text do Console.println(cast(string, frame.payload.toSlice())) }

The client and server validate RFC 6455 upgrades and frame masking. Frames remain visible to the caller, including fragments and control frames; closeGracefully performs the close handshake. WebSocket.connect currently uses an unencrypted ws:// transport. HTTPS requests verify TLS certificates, but the module does not yet expose a reusable TLS stream.

func Http.get #src

Issues a bounded HTTP or HTTPS GET to host, port and an absolute request path. For IPv6, pass the unbracketed address, such as ::1; Net.Url.parseHttp returns it in this form.

path must be absolute, fragment-free and already percent-encoded. HTTPS verifies the peer's certificate and host name using the platform trust store. On Linux, libcurl supplies system trust roots; SSL_CERT_FILE and SSL_CERT_DIR can override the CA file/directory. Linux needs libcurl.so.4 with thread-safe initialization and asynchronous DNS support. Its proxy environment variables, including NO_PROXY, retain libcurl's native behavior. Redirects are returned without being followed unless maxRedirects is nonzero. Redirect following is GET-only, limited to HTTP and HTTPS, and HTTPS requests cannot downgrade to HTTP. Do not combine redirect following with Host, Authorization, Cookie, or Proxy-Authorization headers because those values could be sent to another origin. WinHTTP applies timeoutMs per phase, with coarse enforcement; Linux applies it to the whole transfer, including connection setup. The synchronous operation cannot be cancelled while a native call is blocked. The result owns its body and includes non-success status codes. When bodyHandler is supplied, it receives body chunks during the transfer and Response.body remains empty. All final response headers are returned in received order, preserving duplicate names; Response.location contains the first Location value. Returning false stops the transfer and reports a network error. Invalid input, transport errors, a reached redirect limit, and responses exceeding limits fail without returning a partial result. Linux limits total response headers to 64 KiB and Location to 4096 bytes; Windows limits Location to 8192 bytes of UTF-16 storage. Linux transport failures use libcurl codes in Net.NetworkError.

func Http.post #src

Issues a bounded POST with a request body produced incrementally by bodyReader.

requestBodyLength is exact; the reader must provide that many bytes. The callback receives writable chunks and its state is borrowed for the duration of the call. A missing reader is valid only for an empty body. POST requests do not follow redirects; maxRedirects must be zero. Response handling, certificate validation, timeouts, and cancellation follow Net.Http.get.

func Url.parseHttp #src

Parses an absolute HTTP or HTTPS URL into owned request parts.

This accepts ASCII host names, IPv4 literals, and bracketed IPv6 literals, including IPv4-mapped addresses. IPv6 scope IDs, user information, relative references and non-ASCII URL text are rejected. The path and query stay percent-encoded, an absent path becomes /, and a fragment is omitted. Invalid escapes, malformed ports, overlong DNS names, spaces and control characters fail. DNS names have labels of at most 63 characters and a total of at most 253 characters, excluding an optional final dot.
